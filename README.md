# GameTune

**Программа для Windows 10/11, которая находит реальные причины лагов, применяет только подходящие исправления и честно показывает «до / после» по замерам.**

- **Сначала диагноз, потом лечение.** Никаких наборов твиков «на всякий случай»: каждое изменение привязано к найденной проблеме.
- **Только измеримый результат.** «Стало лучше» — только если замер это доказал. Нет эффекта — изменение помечается или откатывается.
- **Полный откат.** Каждое изменение записывается с исходным значением. Откат — по одному пункту, по сессии или целиком.
- **Честность.** Если проблема в железе (перегрев, мало ОЗУ, HDD, Wi-Fi), программа так и говорит.
- **Безопасность по умолчанию.** Рискованное — только по явному выбору. Никакой «магии»: ни чистки реестра, ни «ускорителей ОЗУ», ни массового отключения служб.

> **Статус: 1.0.0-beta.** Логика покрыта 100+ автоматическими тестами на сохранённых профилях пяти типов ПК. Но на реальных машинах эта версия ещё не проверялась. Первый запуск лучше сделать в виртуальной машине или после ручной точки восстановления. Отчёты о работе на вашем железе очень помогут.

Нужна 64-битная Windows 10 или 11. .NET устанавливать не нужно — он внутри. Программа просит права администратора: без них не прочитать события ядра и не изменить системные настройки. Файлы пока без цифровой подписи, поэтому SmartScreen покажет «Неизвестный издатель» → «Подробнее» → «Выполнить в любом случае».

## Как пользоваться

1. **Главная.** Выберите цель (минимальная задержка, плавность, максимальный FPS, стрим/запись, тихо и холодно) и нажмите «Проанализировать компьютер» (30–60 с, только чтение).
2. **Отчёт анализа.** Найденные проблемы по важности: что не так, почему это важно и на каких данных основан вывод. Аппаратные ограничения помечены отдельно.
3. **Замер «до».** Реальная игра (3 прогона по 60 с), синтетический тест GameTune (полностью воспроизводим, игра не нужна) или PresentMon.
4. **Стратегия.** Список исправлений с галочками: риск, нужна ли перезагрузка, причина. Безопасные отмечены, рискованные — нет.
5. **Применение.** Точка восстановления, журнал, применение. Если нужна перезагрузка, GameTune сам откроется после входа и проверит, что всё применилось и не было синих экранов.
6. **Замер «после»** — в тех же условиях. Программа предупредит, если условия отличаются.
7. **Сравнение.** Карточки «было → стало» с 95 % доверительными интервалами, графики фреймтайма и распределения, режим вывода. Откат по каждому пункту. Экспорт в HTML и CSV.
8. **История.** Все сессии, отчёты, откат любой сессии или всего сразу.

Спорные настройки (HAGS, глобальное разрешение таймера, BCD-таймеры) проверяются **A/B-замером**: текущий вариант → другой (с перезагрузкой, если нужна) → решение. Вариант остаётся, только если он достоверно лучше; иначе возвращается исходный.

### Консольная версия

`gametune-cli.exe` лежит рядом с `GameTune.exe` и делает то же самое из командной строки:

```bash
gametune-cli run --goal latency --mode synthetic
```

```text
gametune-cli run      [--goal latency|smooth|fps|stream|quiet] [--mode game|synthetic|presentmon]   мастер целиком
gametune-cli analyze  [--html report.html] [--dpc 30] [--net]      анализ и отчёт
gametune-cli plan     --goal fps [--profile profile.json]          план и точный список изменений (ничего не меняет)
gametune-cli measure  [--mode …] [--phase before|after]            замер в текущую сессию
gametune-cli apply    [--fix ID,ID] [--option ID:key=value]       применить
gametune-cli ab       --fix HAGS_AB                                A/B-проверка спорной настройки
gametune-cli compare  [before.json after.json] [--html out.html]  сравнение
gametune-cli rollback --fix ID [--session ID] | --session ID | --all
gametune-cli history | report | latency | net | version | doctor   (doctor — проверка окружения)
```

## Что проверяется

Все правила таблицы §3.2 ТЗ и ещё семь:

| Проблема | Важность | Что делает GameTune |
|---|---|---|
| Экран не на максимальной частоте | Критично | Выставляет максимальную частоту |
| Игры могут запускаться на встроенной GPU (гибридная графика) | Критично | Привязывает игры к дискретной GPU, не трогая ваш выбор |
| OBS «Захват экрана» при двух GPU | Критично | Меняет на «Захват игры» (с копией сцен) |
| Перегрев и сброс частот | Критично | Честно говорит: железо. Советы: чистка, подставка, лимит FPS |
| Драйвер с DPC/ISR > 1 мс | Критично | Называет драйвер, советует обновить или отключить устройство |
| Здоровье диска | Критично | Предупреждает, советует резервную копию |
| Устаревший драйвер GPU | Важно | Ссылка на официальный сайт производителя |
| ОЗУ ниже номинала (XMP/EXPO выключен) | Важно | Инструкция для BIOS |
| Мало свободной ОЗУ в простое | Важно | Показывает главных потребителей |
| От сети, но питание экономит | Важно | Режим и параметры питания только для работы от сети |
| OBS от администратора | Важно | Снимает флаг совместимости |
| Нестандартные таймеры BCD | Важно | Возвращает стандарт (с учётом BitLocker) |
| Ключ MPO на Windows 11 24H2+ | Важно | Возвращает стандарт |
| Bufferbloat | Важно | Советует SQM/QoS на роутере |
| Системный диск > 90 % / Windows на HDD | Важно | Советы |
| HVCI, одноканальная память, Wi-Fi, оверлеи, автозагрузка, Game Mode/DVR, оконная оптимизация, TRIM, слабое железо, большой буфер повтора OBS | Совет | Объяснение и, где уместно, исправление |

## Исправления

| ID | Что делает | Риск | Перезагрузка |
|---|---|---|---|
| `DISP_MAX_HZ` | Максимальная частота экрана при текущем разрешении | безопасно | — |
| `GPU_PREF_DGPU` | «Высокая производительность» для игр в настройках графики Windows | безопасно | — |
| `WIN_WINDOWED_OPT` | Оптимизация оконных игр и VRR (Windows 11), остальные глобальные настройки DirectX сохраняются | безопасно | — |
| `GAME_MODE_ON` / `GAME_DVR_OFF` | Игровой режим вкл., фоновая запись Game Bar выкл. | безопасно | — |
| `MPO_RESET` | Удаляет `OverlayTestMode` | безопасно | да |
| `POWER_SCHEME_PERF` | Схема «Высокая производительность» (только ПК) | безопасно | — |
| `POWER_AC_TUNING` | От сети: режим «Максимальная производительность», 100 % CPU, без парковки ядер (ПК), USB/PCIe/Wi-Fi без энергосбережения | безопасно | — |
| `NET_ADAPTER_POWER_OFF` | Запрет отключения сетевого адаптера для экономии энергии | безопасно | — |
| `STARTUP_DISABLE` | Отключает только выбранные вами пункты автозагрузки (как Диспетчер задач) | безопасно | — |
| `OBS_NO_ADMIN` | Убирает «Запуск от администратора» у OBS | безопасно | — |
| `OBS_GAME_CAPTURE` | «Захват экрана» → «Захват игры» в сценах OBS | умеренно | — |
| `POWER_THROTTLING_OFF` | Отключает Power Throttling | умеренно | да |
| `BCD_TIMERS_RESET` | Удаляет `useplatformclock` / `useplatformtick` | умеренно | да |
| `HAGS_AB` | HAGS вкл./выкл. — только по A/B-замеру | умеренно | да |
| `TIMER_RES_GLOBAL` | `GlobalTimerResolutionRequests` (Windows 11) — только по A/B-замеру | умеренно | да |

Только советы (программа сама не меняет): драйверы, XMP/EXPO, MUX, чистка от пыли, настройки панели NVIDIA/AMD, оверлеи чужих программ, роутер.

## Как устроено честное сравнение

- Метрики: средний FPS, 1 % и 0,1 % low (среднее худших кадров), фреймтайм — медиана, p95, p99, стандартное отклонение. Источник — события Present (как `MsBetweenPresents` в PresentMon).
- Первые секунды прогрева отбрасываются; по умолчанию 3 прогона по 60 с.
- 95 % доверительный интервал — **блочный бутстреп** (блоки примерно по 1 с, так учитывается, что соседние кадры зависят друг от друга).
- «Лучше» / «хуже» — только если интервалы не пересекаются **и** разница больше разброса между прогонами. Иначе — «в пределах шума».
- Прогоны с троттлингом исключаются; разные условия (процесс, разрешение, экран, питание) делают сравнение «ненадёжным».

## Безопасность

- Система меняется только через `ChangeContext`. Сначала исходное значение записывается в журнал `C:\ProgramData\GameTune\journal.db`, потом меняется настройка. Не удалось сохранить исходное значение — изменение не выполняется.
- Исходное значение фиксируется один раз: повторное применение не затирает оригинал.
- Исправление, упавшее посередине, откатывает свои частичные изменения.
- Файлы (сцены OBS) копируются в `C:\ProgramData\GameTune\backups\`.
- Перед первым применением создаётся точка восстановления Windows (если защита системы включена).
- В игры ничего не внедряется: кадры читаются из ETW, поэтому античиты не реагируют.
- Телеметрии нет. Сеть используется только для проверки обновлений (можно выключить) и для теста сети по вашей команде.
- При удалении установщик предлагает откатить все изменения. Журнал остаётся в `ProgramData`.

## Ограничения

- Бета-версия: реальная проверка на 5–10 разных ПК (§11 ТЗ) ещё впереди.
- Температура CPU — из ACPI (приблизительно); температура GPU и троттлинг — для NVIDIA через `nvidia-smi`.
- Режим вывода (Independent Flip) и задержка — только при замере через PresentMon. Его можно положить рядом с программой или указать путь в настройках.
- Исправления в HKCU (привязка GPU, Game Mode) пишутся для пользователя, от имени которого запущена программа.
- Наличие MUX определяется косвенно.
- `POWER_THROTTLING_OFF` действует глобально: постоянного отключения для отдельного процесса Windows не даёт.
- Профили NVIDIA/AMD через NVAPI/ADLX — в следующей версии.
